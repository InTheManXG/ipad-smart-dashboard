# beta.3 实际验收记录

本记录区分自动化检查、独立 Mac 的实际操作和未验证范围，不将构建通过等同于所有设备兼容。

## 环境与发布附件

- 验收日期：2026-11-16。
- 独立设备：Apple M1 Mac mini，macOS 27.0.1，Apple Silicon / arm64；首次安装前没有本 App 的安装、配置、后台进程或登录项。
- 网页端：桌面浏览器；另一个独立 HTTP 会话用于确认逐端权限隔离。此处不包含实际 iPad 验收。
- 新版来源：当时 `v0.1.0-beta.3` Release 的 `iPad-Control-0.1.0-beta.3-unnotarized-macos-arm64.zip`。该预发布发行页现已清理；[源码标签](https://github.com/InTheManXG/ipad-smart-dashboard/tree/v0.1.0-beta.3)和[原始打包记录](https://github.com/InTheManXG/ipad-smart-dashboard/actions/runs/43826336624)保留。
- ZIP SHA-256：`1afa0c0f1d7b5b4fc31f0294291f07ef38dff324a6aa889adb18a1b6ddba0225`。下载后按随附 `SHA256SUMS` 校验通过，并验证严格签名结构。
- 测试机的 Gatekeeper 在验收前已关闭，本次没有修改系统安全设置。因此以下运行结果不代表 Gatekeeper 接受、单 App 放行、开发者身份认证或 Apple 公证。

## 独立 Mac 实际结果

| 项目 | 操作与观察 | 结果 |
| --- | --- | --- |
| 首次安装与入口 | 安装完整 App 后打开；主窗口、Dock 与菜单栏入口均可见。首次状态无公网地址，看板、音乐及两个登录启动开关均关闭。 | 通过 |

| 临时控制授权 | 经用户确认，在 App 为测试网页开启控制；网页确认执行已配置的临时命令，实际临时文件内容为 `verified`。 | 通过 |
| 撤回控制 | 在 App 撤回该网页权限，网页控制按钮变为禁用；另一测试会话始终保持只读。 | 通过 |
| 多端与踢下线 | 踢掉其中一个网页后，另一会话的状态及权限接口继续返回 200。被踢网页清空历史任务、控制台与额度；网页曾停在连接中，重新加载后实际出现配对窗口。 | 通过；只确认返回配对入口，未再次建立配对 |

| 登录启动配置 | 分别切换两个登录启动选项，回读对应 LaunchAgent 的 `RunAtLoad`、`KeepAlive` 及程序路径；测试后恢复关闭。 | 配置验证通过；未注销并重新登录 |
| 关闭窗口与退出 | 关闭主窗口后从菜单栏重新打开成功，窗口约一秒后出现；使用退出菜单后，App 与后台进程均停止，监听端口关闭。 | 通过 |

## 同一 Mac 的版本替换与数据保留

旧版从已发布的 `v0.1.0-beta.2` 精确标签源码构建，版本为 `0.1.0-beta.2`、构建号为 `1`，严格签名检查通过。beta.2 当时仅发布源码，因此本次不声称使用历史 beta.2 安装附件。新版使用上文从 GitHub 下载并校验的 beta.3 ZIP。

在同一 Mac、同一安装位置退出旧版并替换完整 App 后，实际核对：

- `installation.json` 的安装绑定和钥匙串账户后缀保留。
- `settings.json`、`local-screens.json`、`console-actions.json` 的稳定字段保留，包括服务设置、配对标识、权限、测试备注和快捷项目；会话最近访问时间不作为不变字段。
- 原浏览器配对会话继续可用，并保持撤权后的只读状态。
- beta.2 启动时出现钥匙串授权，由用户在系统界面完成；替换回 beta.3 后没有再次出现授权窗口，原配对会话继续工作。测试没有配置真实中转站 Key，不能据此宣称其 Key 或钥匙串升级交互已验收。

这证明该版本替换场景保留了现有配置，不覆盖任意历史版本、跨 Mac 迁移或所有钥匙串项目。

## 清理与最终状态

临时控制权限已经撤回；两个测试会话均已撤销，随后清空了仅含测试记录的配对文件。临时快捷命令、测试结果文件及配置比较快照已删除。两个登录启动选项恢复关闭，公网地址为空，看板与音乐关闭。完整 App 保留在测试用户的“应用程序”目录，App 与后台均已退出，两个 LaunchAgent 均未加载。

## 0.2.1 自动更新验收（2026-11-17）

在本机 Apple Silicon Mac、macOS 27.2 上，从固定开发证书签名的更新引导版本（显示 0.1.0、构建 1，已加入本次更新器）实际升级到 GitHub Actions 生成的 0.2.1、构建 9。该引导版本仅用于验收，不是已发布的原始 0.1.0；没有更新器的旧发行包仍需手动安装一次新版。

- [正式发行](https://github.com/InTheManXG/ipad-smart-dashboard/releases/tag/v0.2.1)、[发行构建](https://github.com/InTheManXG/ipad-smart-dashboard/actions/runs/44030515123)、[标签持续检查](https://github.com/InTheManXG/ipad-smart-dashboard/actions/runs/44030515090)及[源码持续检查](https://github.com/InTheManXG/ipad-smart-dashboard/actions/runs/44030475628)均通过。
- 在“关于”点击检查后，真实发现 0.2.1，完成 GitHub ZIP 下载、验签、安装及自动重启；新版关于页显示 0.2.1（9）和“当前已是最新版本”。
- 进程记录确认 App 与后台均更换 PID，最终仅有一个后台服务；心跳恢复到一秒内，本地看板端口重新监听，公网配对仍为有效。
- `settings.json`、`installation.json`、`console-actions.json` 的 SHA-256 前后一致，云端网页权限稳定字段摘要一致；未输出、导出或修改用户 Key。更新后九个签名组件均通过固定开发证书及严格签名检查。
- 官方工具验证线上签名更新源；篡改更新源和错误私钥均被拒绝。实际安装文件另与 GitHub ZIP 中的 App 比较。

此验收没有覆盖其他 macOS、无写入权限的安装目录、系统管理员授权、更新过程中断电或断网，也不代表 Apple 公证或 Gatekeeper 首次放行。之前的后台额度采集偶发异常仍未修复。


## 0.3.0 音乐布局验收（2026-11-17）

[发行构建](https://github.com/InTheManXG/ipad-smart-dashboard/actions/runs/44053715089)和[持续检查](https://github.com/InTheManXG/ipad-smart-dashboard/actions/runs/44053715241)通过。App 从 0.2.6 经内置更新升级到 0.3.0（构建 15），固定签名验证通过，后台与公网配对恢复。

在 Mac“音乐同步”中依次选择音乐优先、全屏音乐，本地 HTTP 和既有公网 HTTPS 网页均在轮询后采用相同布局。音乐优先的播放器位于任务上方，内容高度约为任务区两倍；全屏音乐复用唯一播放器节点并增加独立横向页面，任务和音乐可经链接或滑动切换。关闭同步时两端移除音乐页面并回到任务页，重新启用仍采用全屏音乐。验收后恢复原有标准布局和启用状态。

浏览器验证包含 1194×834 与 390×844 视口、刷新恢复、页面增减和旋转定位。此处是桌面浏览器视口测试，未在实际 iPad 上复测。新回归覆盖 248 项原生断言、41 项 Python 测试及 7 组网页测试；单实例检查继续通过。

公网更新沿用原 1Panel 目录，仅应用本次布局相关的六个文件差异；保留既有网页品牌和独立修改，备份程序及配对数据库后重启同一服务，健康检查和公网静态资源校验通过。部署没有删除配对数据。
